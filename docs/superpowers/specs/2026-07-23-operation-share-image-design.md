# 作业分享图片功能设计

- 状态：已确认
- 日期：2026-07-23
- 语言：zh-CN

## 背景

`OperationDrawer` 负责根据 URL 参数打开作业详情，实际作业数据与工具栏位于
`OperationViewer`。用户需要把作业的核心信息转换为图片，以便预览、下载和分享。

## 目标

- 在作业详情工具栏增加“生成分享图”按钮。
- 生成包含作业标题、关卡、作者、密探及密探组、动作序列的 PNG。
- 生成后先展示真实 PNG 预览，再由用户下载。
- 保证分享图不受抽屉宽度、折叠状态和明暗主题影响。
- 图片功能按需加载，不增加作业详情首屏的必要包体。

## 非目标

- 不截取整个作业详情界面。
- 不包含点赞、评论、发布时间和作业详情正文。
- 不在本期接入服务端图片生成、图片上传或社交平台分享 API。
- 不改变现有 JSON 下载、神秘代码或复制到编辑器功能。

## 用户交互

1. 用户点击作业详情工具栏中的“生成分享图”。
2. 应用打开预览弹窗并显示生成进度。
3. 应用等待字体和头像加载，生成 PNG Blob，并展示该 PNG 的预览。
4. 用户可下载 PNG、重新生成或关闭弹窗。
5. 关闭弹窗时释放临时 Object URL。

生成期间禁用重复生成操作。生成失败时弹窗保持打开，显示可理解的错误信息和
“重新生成”按钮。

## 架构与组件边界

### `OperationViewer`

- 在现有工具栏新增带图片图标的“生成分享图”按钮。
- 只管理弹窗打开状态，并把已加载的 `operation` 传给分享功能。
- 不发起第二次作业请求。

### `OperationShareDialog`

- 管理 `idle`、`generating`、`ready`、`error` 状态。
- 渲染用于捕获的 `OperationShareCard`。
- 动态导入图片转换模块并生成 Blob。
- 展示生成后的真实 PNG，而不是仅预览待捕获 DOM。
- 管理重新生成、下载和 Object URL 生命周期。

该组件及图片生成依赖通过动态导入加载，避免进入详情页初始必要包体。

### `OperationShareCard`

- 是固定 `1080px` 宽的纯展示组件。
- 只接收规范化后的分享模型，不读取路由、认证状态或远程 API。
- 固定使用浅色主题和明确的背景色。
- 对头像使用同源本地资源，并在生成前完成预加载。

### 分享展示模型

从 `Operation` 派生一个只包含图片所需字段的模型：

- 作业标题、关卡名、作者。
- 密探站位、名称、头像、技能序号、等级和模组；缺失字段不显示占位值。
- 密探组名称及其可替换密探。
- 按回合排序的动作，以及不能归属到站位的额外动作。

现有 `ActionSequenceViewer` 中的回合、站位和动作标签转换逻辑提取为纯函数，网页
查看器和分享卡片共同使用，避免两套转换规则产生差异。

## 视觉设计

- 图片宽度固定为 `1080px`，高度随内容增长。
- 页首突出作业标题，并紧凑展示关卡和作者。
- 密探区采用五列布局，展示头像、名称、站位、技能序号、等级和模组。
- 密探组以“可替换密探”区块展示。
- 动作区使用表格语义：行表示回合，列表示密探站位，末列容纳额外动作。
- 动作标签保留现有颜色语义和执行顺序。
- 无密探或无动作时展示明确的空状态，不阻止生成图片。

预览弹窗在桌面和移动端均可滚动，图片按可用宽度缩放，但不改变原始导出尺寸。

## 图片生成

使用 `html-to-image` 将专用分享卡片转换为 PNG Blob：

1. 等待 `document.fonts.ready`。
2. 等待捕获节点内所有头像加载并调用 `decode()`；加载失败时应用现有占位图，
   全部资源等待最长 `5s`。
3. 动态导入 `html-to-image` 并调用 `toBlob`。
4. 显式设置浅色背景和像素倍率。
5. 使用 Blob 创建预览 URL，下载时复用同一 Blob。

默认像素倍率为 `2`。根据卡片高度自动降低倍率，使导出高度尽量不超过
`16000px`，降低浏览器 Canvas 尺寸超限风险。倍率不低于 `1`；若 `1x` 仍无法
生成，进入错误状态并允许重试。

下载文件名格式为“关卡名-作业标题.png”，并过滤文件系统非法字符；字段为空时
使用稳定的后备名称。

## 错误处理

- 单个头像加载失败：换用占位图，继续生成。
- 字体或图片等待超过 `5s`：继续使用已加载资源尝试生成，并记录警告。
- PNG 转换返回空 Blob 或抛出异常：进入错误状态，不触发下载。
- 重复生成：撤销旧 Object URL 后再创建新 URL。
- 弹窗关闭或组件卸载：撤销当前 Object URL，避免内存泄漏。

## 测试策略

仓库当前没有自动化测试框架。新增轻量 `Vitest` 和 `test` 脚本，不引入完整组件
测试栈。实现遵循测试先行，优先覆盖纯逻辑和资源生命周期：

- 分享模型正确映射元信息、密探、密探组、回合动作和额外动作。
- 空数据和不完整旧格式作业可安全转换。
- 文件名过滤非法字符并提供后备名称。
- 长图片像素倍率计算符合上下限。
- 生成失败、重新生成和 Object URL 释放行为正确。

完成后运行完整测试、ESLint、Prettier 检查和 TypeScript/Vite 构建。浏览器验收覆盖
普通作业、长动作序列、缺失头像、暗色站点主题和移动端预览。

## 验收标准

- 工具栏按钮能打开预览弹窗，且不会重复请求作业。
- 预览内容是最终下载的真实 PNG。
- PNG 包含已确认的元信息、全部密探信息和完整动作序列。
- 输出始终为清晰、无重叠的浅色图片。
- 长图可生成，移动端可以完整预览并下载。
- 生成失败可重试，临时资源在替换或关闭后被释放。
- 测试、代码风格检查和生产构建全部通过。

## 风险与权衡

- `html-to-image` 是新增运行时依赖；通过动态导入控制初始包体影响。
- 超长 Canvas 的上限因浏览器而异；通过自适应倍率降低失败概率，不在本期拆分多图。
- 分享卡片会复用动作展示模型，但保持独立视觉组件，以免现有抽屉响应式样式影响导出。
